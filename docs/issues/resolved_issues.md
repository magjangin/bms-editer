## 🔊 B. 키음 다중 채널 믹싱 재생

* **이전 문제**: Win32 `PlaySound(SND_ASYNC)`를 사용하여 단일 채널로 재생되었기 때문에, 화음이나 빠른 연타 시 앞선 소리가 끊기고 채보 귀 검수가 불가능했습니다.
* **해결 구조**:
  - `WavDecoder`를 통해 WAV (8/16/24/32bit PCM, IEEE Float, `WAVE_FORMAT_EXTENSIBLE`) 및 OGG 파일을 44100Hz 16-bit Stereo PCM으로 백그라운드 사전 디코딩하여 메모리에 캐싱.
  - Win32 `waveOut` 네이티브 헤더(`WAVEHDR`) 포인터를 직접 제어하는 `KeySoundPlayer` 스트리밍 믹서를 구축하여 포화 가산(Saturation Clamping)으로 실시간 다중 채널(폴리포닉) 믹싱을 완벽 지원합니다.

## 🎛 F. 컨트롤 패널: 집계에서 키음으로 노트 찾기

한때 통계 창에 있었다가 **걷어냈던** 기능입니다. 이번에 **🎛️ 컨트롤 패널**이라는 별도 창으로 다시 만들어 넣었습니다.
(`ControlPanelViewModel` · `ControlPanelWindow`)

### 왜 접었었나

만드는 동안 세 번 헛돌았고, 매번 원인이 달랐습니다.

| 시도 | 무엇이 문제였나 |
|------|----------------|
| 1 | 명령을 `{Binding $parent[ItemsControl].((vm:NoteStatsViewModel)DataContext).…}` 로 끌어왔는데, 컴파일된 바인딩에서 **조용히 실패**했습니다. `Command` 가 null 인 버튼이라 눌러도 아무 일이 없었고, 빌드도 예외도 멀쩡했습니다 |
| 2 | 버튼 스타일(`Background`·`BorderBrush`)이 **Fluent 테마의 Button 템플릿에 가려** 화면에 안 나타났습니다. 누를 수 있다는 표시가 없으니 누를 생각을 할 이유도 없었습니다 |
| 3 | `ListBox` 로 바꿔 동작은 했지만, 고른 노트가 화면 밖이면 여전히 눌렸는지 알기 어려웠습니다. 격자를 그리로 스크롤하고 안내문을 붙이며 덧대다 보니 통계 창의 몫이 아닌 일이 늘었습니다 |

### 이번에는 무엇을 다르게 했나

| 예전에 걸린 것 | 이번 방식 |
|----------------|-----------|
| 목록 항목 안에서 조상 바인딩으로 명령을 끌어옴 | **목록 항목에는 명령을 걸지 않습니다.** 고른 줄은 `SelectedItem` 으로만 받고(`SelectedLaneStat`·`SelectedWavStat`), 누르는 것은 전부 목록 **밖**의 버튼입니다. 창의 `DataContext` 가 곧 뷰모델이라 바인딩이 한 칸도 건너뛰지 않습니다 |
| 버튼이 테마 템플릿에 가려 안 보임 | 항목 안에 버튼을 두지 않으니 가려질 자리 자체가 없습니다. 고른 줄은 검색 창·팔레트와 같은 파랑(`#3B6FD4`)으로 강조합니다 |
| 고른 노트가 화면 밖이면 눌렸는지 알 수 없음 | 선택을 `NoteSelectionSource.Search` 로 알려 **그 자리로 스크롤**시키고(`ScrollToRatioRequested`), 결과를 창 아래 한 줄(`StatusMessage`)로 말해 줍니다 |
| 뷰모델은 멀쩡한데 화면에서 끊어짐 | 창을 실제로 띄워 **작업 버튼 6개에 `Command` 가 붙어 있는지** 확인하는 테스트를 넣었습니다(`WindowSmokeTests`) |

검색 창과 역할이 겹치지 않느냐는 판단은 이렇게 갈랐습니다.
**"이 번호가 몇 개 있나"에서 곧장 손대는 것**은 컨트롤 패널이 맡고,
**"조건을 조합해 찾는 것"**(마디 범위 · 노트 종류 · 여러 레인)은 그대로 검색 창의 몫입니다.
컨트롤 패널의 일괄 작업은 언제나 **고른 줄 하나**를 대상으로 합니다.

> 📊 통계 창은 **보기 전용으로 남겨 두었습니다.** 숫자만 볼 때 잘못 눌러 수백 개가 바뀌는 일이 없고,
> 집계 규칙은 `NoteStatsViewModel` 한 곳뿐이라 두 창의 숫자가 갈라지지 않습니다.

> 되돌리기가 아직 없으므로([C](known_issues.md#-c-undo--redo)), 컨트롤 패널의 **일괄 삭제는 늘 먼저 물어봅니다.**
> (검색 창의 [삭제]·[번호 일괄 변경]은 20개 이상일 때만 묻습니다 — S-5, `aa685e4`)
> 확인 창을 띄울 길이 없으면(`ConfirmAsync` 가 없으면) 아무것도 지우지 않습니다.

> 패널 맨 위의 열(레인) 선택 칸은 모양을 다시 볼 자리로 남겨 두었습니다 → [known_issues 🅿️](known_issues.md#-나중에-고려-패널-맨-위의-열레인-선택-칸)

## 🛟 G. 안전장치

`aa685e4` 에서 2026-09-23 점검의 S-1~S-5·S-7 을 한꺼번에 고쳤습니다([점검 때 적었던 원래 기록](#-점검-때-적었던-원래-기록)). S-6(좌클릭 즉시 배치)은 되돌리기([C](known_issues.md#-c-undo--redo))의 몫이라 남겨 두었습니다.

**파일은 전부 `%LocalAppData%\bms editer\` 아래에 있습니다.** 파일 메뉴의 **[자동 저장·오류 기록 폴더 열기]** 로 바로 열립니다.

| 폴더 | 무엇이 있나 |
|------|-------------|
| `recovery\snapshots\<곡폴더>_<파일명>_<해시>\` | 문서마다 한 폴더. `…_auto.bms` 는 자동 저장본, `…_before-save.bms` 는 [저장]이 덮어쓰기 직전의 파일. 종류별로 최근 **10벌**만 남고, 한 달 넘게 안 쓴 문서 폴더는 지웁니다. 옆의 `.json` 은 원래 경로·인코딩 기록입니다 |
| `recovery\sessions\` | 실행 중인 앱마다 파일 하나. 정상 종료하면 지워집니다 |
| `logs\` | 오류 기록 `error-*.log`. 최근 30건만 남깁니다 |

**어떻게 동작하나**

| 상황 | 동작 |
|------|------|
| 편집 중 | 저장 안 된 변경이 있으면 **2분마다** 자동 저장합니다. 그 사이 바뀐 게 없으면 새로 쓰지 않습니다 |
| [저장] | 덮어쓰기 직전의 파일을 저장 이력으로 옮겨 둡니다(곡 폴더의 `.bak` 은 여전히 한 벌). 바로 앞 이력과 똑같으면 또 만들지 않습니다 |
| 예상하지 못한 예외 (UI 스레드) | 앱이 꺼지지 않습니다. 재생을 멈추고, **그 자리에서 비상 저장**하고, 오류 기록을 남긴 뒤 "오류" 창에서 [계속 작업]/[끄기]를 묻습니다. 비상 저장에 실패하면 그 사실을 창에 적습니다([H-7](#-h-2026-09-28-점검에서-찾아-고친-것)). [끄기]는 저장 안 된 변경이 있으면 늘 쓰던 "저장하고 닫을까요?" 로 이어집니다. 창이 떠 있는 동안 또 나면 기록만 남깁니다 |
| 앱이 죽었다 (강제 종료·전원 등) | 다음 실행 때 **"작업 복구"** 창이 뜹니다. [복구] 는 마지막 자동 저장본을 원래 자리의 문서로 되살리고(음원·영상도 다시 붙임) "저장 안 됨(`*`)" 상태로 둡니다. 원래 파일은 [저장]을 눌러야 바뀝니다. [복구 안 함] 은 묻지 않게 하고(자동 저장본은 남음), [취소] 는 다음 실행 때 다시 묻습니다 |
| 저장 안 된 작업 없이 죽었다 | 묻지 않고 세션 파일만 치웁니다 |
| 창 두 개 | 서로의 세션을 "죽었다"고 보지 않습니다(프로세스 번호와 시작 시각으로 가립니다) |
