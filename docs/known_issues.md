## 🔴 1. 3자리 키음 차트에 키음을 추가하면 기존 키음이 덮어써진다

### 증상
키가 `#001`, `#00A`, `#01Z` 처럼 **3자리**인 차트에서 `[키음 추가]`를 하고 저장하면,
새 키음이 **기존 `#001`을 덮어씁니다.** 001번을 쓰던 모든 노트가 다른 소리로 바뀝니다.
아무 경고도 뜨지 않습니다.

### 원인
* [MainWindowViewModel.cs](file:///h:/source/repos/bms%20editer/bms%20editer/ViewModels/MainWindowViewModel.cs) 의 `GetNextWavKey()` 는 **항상 2자리 키만** 만듭니다.
  기존 키가 전부 3자리(`001`~)이므로 2자리 `01` 은 "비어 있는" 키로 판정됩니다.
* [BmsWriter.cs](file:///h:/source/repos/bms%20editer/bms%20editer/Services/BmsWriter.cs) 는 3자리 차트를 만나면 `keyWidth = 3` 으로 잡고
  `PadLeft(3, '0')` 으로 폭을 맞춥니다. 그래서 `01` → `001` 이 되어 충돌합니다.
* 참고로 검색/삭제/교체 창(`NoteSearchViewModel`)은 키 폭을 제대로 다룹니다.
  즉 이건 의도된 동작이 아니라 `GetNextWavKey()` 쪽이 빠뜨린 것입니다.

### 재현 결과
```
[키음 추가] 가 만들어낼 새 키: "01"   (기존 키는 전부 3자리)

=== 저장 결과 ===
  #WAV001 snd001.wav
  #WAV002 snd002.wav
  #WAV003 snd003.wav
  #WAV001 새키음.wav        <-- 충돌

다시 읽으면 001 이 가리키는 파일: 새키음.wav
```

### 확인 방법
> ⚠️ **반드시 사본으로 하세요. 원본 차트가 손상됩니다.**

1. 3자리 키음 차트를 사본으로 연다
2. 키음 팔레트에서 `[키음 추가]` 로 아무 WAV나 넣는다
3. 저장 후 다시 연다
4. `#001` 이 원래 파일을 가리키는지 확인한다

## 🟠 2. "격자에 맞추기(G)" 체크박스가 아무 일도 하지 않는다

`SnapToGrid` 속성은 [MainWindow.axaml](file:///h:/source/repos/bms%20editer/bms%20editer/MainWindow.axaml) 의 체크박스에 바인딩되어 있을 뿐
**코드 어디에서도 읽히지 않습니다.** 노트 배치는 체크 상태와 무관하게 항상 격자로 반올림됩니다.

**확인 방법**: 체크를 끄고 격자 사이에 노트를 찍어봅니다. 그래도 격자에 붙으면 확정입니다.

`LockVerticalPosition` 역시 바인딩만 있고 소비하는 곳이 없습니다. 2번과 동일합니다.

## 🟠 4. 방향키로 노트를 옮기면 현재 격자로 강제 스냅된다

### 증상
`MoveNoteInTime` 이 `Math.Round((Measure + Position) * split)` 으로 위치를 다시 계산합니다.
그래서 **현재 격자로 표현할 수 없는 위치의 노트는 옮기는 순간 위치 자체가 바뀝니다.**
3잇단음처럼 12분할로 찍은 노트를 16분할 상태에서 건드리면 잇단음이 깨집니다.

### 확인 방법
1. 격자를 `12` 로 두고 3잇단음을 찍는다
2. 격자를 `16` 으로 바꾼다
3. 그 노트를 방향키로 한 칸 옮긴다 → 위치가 16분음표로 뭉개지는지 본다

## 🟠 5. 노트가 겹치면 저장할 때 하나가 조용히 사라진다

[BmsWriter.cs](file:///h:/source/repos/bms%20editer/bms%20editer/Services/BmsWriter.cs) 가 `slots[index] = code` 로 덮어쓰기 때문에,
같은 마디·레인·위치에 노트가 둘 있으면 **마지막 하나만 남습니다.**

겹치게 만드는 경로가 있습니다. `IsSlotOccupied` 가 **선택된 노트를 검사에서 제외**하므로,
여러 개를 선택해 이동시킬 때 일부가 막히면 남은 노트 위로 겹쳐 올라갈 수 있습니다.

---

## 🟠 6. 그룹 이동 시 일부만 움직여 모양이 깨진다

`MoveNoteInTime` 은 마디 범위를 벗어나거나 슬롯이 차 있으면 **그 노트 하나만** 조용히 건너뜁니다.
선택 전체가 취소되는 것이 아니라서 상대 간격이 무너집니다.

**확인 방법**: 노트 여러 개를 선택하고, 앞이 막힌 방향으로 방향키를 눌러봅니다.

## 🟡 7. 그 밖에 확인이 필요한 것들

| # | 증상 | 확인 방법 |
|---|---|---|
| 7-1 | **Delete·방향키가 격자에 포커스가 있을 때만 동작한다.** 팔레트나 사이드바를 만진 뒤에는 먹지 않고 안내도 없다 | 팔레트에서 키음을 고른 직후 Delete 를 눌러본다 |
| 7-2 | **곡 마지막 마디에 노트를 못 찍을 수 있다.** `measure >= MeasureCount` 면 배치를 거부하는데 `MeasureCount` 는 오디오 길이에서 올림 계산한다 | 곡 맨 끝 마디에 찍어본다 |
| 7-3 | **우클릭 삭제 허용오차가 배치보다 50배 넓다** (배치 `0.0001` / 삭제 `0.005`) | 격자를 192 로 두고 촘촘히 찍은 뒤 하나만 우클릭한다. 옆 노트가 같이 지워지는지 본다 |
| 7-4 | **키음이 1295개를 넘으면 `[키음 추가]` 가 조용히 실패한다.** `GetNextWavKey` 가 던진 예외를 `AddWav` 가 삼킨다 | 키음이 많은 차트에서만 재현된다 |
| 7-5 | **저장 성공 표시가 없다.** 실패만 알림창이 뜬다 | 저장을 눌러도 아무 반응이 없는 것이 정상 동작이다 |
| 7-6 | **파일 안의 주석(`*----` 줄)이 저장할 때 사라진다.** `#` 로 시작하지 않아 원문 보존 대상에서 빠진다 | 주석이 있는 차트를 열고 저장한 뒤 비교한다 |
