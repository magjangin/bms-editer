# 🎮 게임 프로파일 — 게임별 값 한 곳

> [!NOTE]
> **게임마다 다른 값만 모아 둔 단일 표입니다.** 어떤 레인을 쓰는지, 홀드를 무엇으로 판별하는지,
> 실제로 만들어 봤는지를 여기 한 곳에서만 관리합니다.
>
> 짝을 맞추는 **규칙과 알고리즘**은 게임과 무관하므로 [🔗 홀드 짝 맞추기 사양](hold_pairing_spec.md) 에 있습니다.
> 작성 **시간**과 개선 후보는 [⏱️ authoring_time.md](../issues/authoring_time.md) 에 있습니다.

> [!IMPORTANT]
> **게임을 추가할 때 손볼 곳은 세 군데입니다.** 아래 표에 한 줄 + 프로파일 JSON 하나 + `guides/` 에 가이드 하나.
> 예전에는 같은 게임 표가 문서 다섯 곳에 흩어져 있어서, 실제로 DEFLATE 가이드가 **다섯 곳 전부에서 누락**됐습니다.
> 다른 문서들은 이제 이 표로만 링크합니다. **여기에 없는 게임은 어디에도 없는 것으로 취급하십시오.**

## 📋 1. 프로파일 표

| 게임 | 프로파일 id | 편집 레인 | 키 폭 | 홀드 판별 전략 | 상태 | 가이드 |
|:---|:---|:---|:---:|:---|:---:|:---|
| **스타트레일** | `startrail` | Solar: `11` `12` `14` `15` + `16`<br>Lunar: `11`~`15` + `16` `18` | 2 | **① KeyValue** | ✅ 실측 완료 | [sixtar_gate_startrail.md](../guides/sixtar_gate_startrail.md) |
| **스타게이저** | `stargazer` | `16` `12` `13` `11` | 2 | **② FileNameKeyword** | ✅ 실측 완료 | [sixtar_gate_stargazer.md](../guides/sixtar_gate_stargazer.md) |
| **건볼트** | `gunvolt` | `16` `11` `12` / `14` `15` `18` | 2 | **① KeyValue** (아크는 N:M) | ✅ 실측 완료 | [gunvolt_records_cychronicle.md](../guides/gunvolt_records_cychronicle.md) |
| **DEFLATE** | `deflate` | `16` `11` `12` `13` + `14`(드롭) | 3 | **② FileNameKeyword** | ⬜ 키음 확인 | [deflate.md](../guides/deflate.md) |
| ~~**뮤즈 대시**~~ | `muse_dash` | `13` `14` `15` `18` | 2 | **③ OccurrenceParity** | **❌ 지원 제외** | [muse_dash.md](../guides/muse_dash.md) |

`✅ 실측 완료` = 실제 게임 BMS 차트(MARENOIA, shut up, Discotic Night 등)를 읽고 짝/렌더링 검증 완료  
`❌ 지원 제외` = 6자리 UID 체계 및 출현 순서 전파(Cascade)로 인한 극심한 난이도와 시간 소요로 **공식 지원 대상에서 제외**

> [!CAUTION]
> **뮤즈 대시 지원 제외 안내**  
> 뮤즈 대시는 6자리 UID 지정과 채널 내 출현 순서(홀수=시작, 짝수=끝) 기반의 페어링 규칙을 사용합니다.
> 중간에 노트 하나를 수정하거나 끼워 넣으면 이후의 모든 홀드가 뒤집히는 연쇄 전파(Cascade)가 발생하여, 실측 340노트에 4시간 이상이 소요되는 등 제작 난이도가 극히 높습니다.
> 이에 따라 **BMS Editer의 공식 지원 및 채보 작성 대상에서 제외**합니다.

### 전략이 셋뿐인 이유

위 표의 "전략" 열에 값이 **3종류뿐**입니다. BMS에서 홀드를 표시할 수 있는 자리가 물리적으로 그만큼이기 때문입니다.

| 전략 | 쓰는 게임 | 비고 |
|:---|:---|:---|
| ① KeyValue (슬롯 코드 값) | 스타트레일, 건볼트 | 코드 기반 N:M 및 게이트 지원 |
| ② FileNameKeyword (파일명) | DEFLATE, 스타게이저 | 파일명 키워드 부분일치 |
| ③ OccurrenceParity (출현 순서) | ~~뮤즈 대시~~ | **작업 난이도 과다로 제외됨** |

## 🔧 2. 전략 파라미터

프로파일 JSON에 들어갈 값입니다. 규칙의 의미는 [hold_pairing_spec.md §6](hold_pairing_spec.md) 을 보십시오.

### DEFLATE (`deflate`) — ② FileNameKeyword

| 항목 | 값 |
|:---|:---|
| Head 키워드 | `홀드 시작` `홀드시작` `hold start` `holdstart` `hold_start` `ln start` `lnstart` |
| Tail 키워드 | `홀드 끝` `홀드끝` `hold end` `holdend` `hold_end` `ln end` `lnend` |
| 필수 키워드 | 없음 |
| `tailFirst` | **`true`** — 양쪽을 다 담은 파일명은 Tail |
| `requireMatchingBaseName` | `false` — 같은 채널의 아무 Tail이나 Head를 닫는다 |
| `nestingPolicy` | `Fifo` |

> [!CAUTION]
> **홀드 쌍 키음이 번호 순서와 반대입니다.** `00B`=시작 / `00A`=끝, `00D`=시작 / `00C`=끝 …
> 팔레트에서 번호만 보고 고르면 뒤집힙니다. → 팔레트 역할 뱃지([spec §8](hold_pairing_spec.md))가 이걸 막습니다.
>
> 레인 `15`·`18` 에 찍은 노트는 **경고 없이 조용히 사라집니다.** 드롭 레인(`14`)에는 홀드 쌍이 없습니다.

### 스타게이저 (`stargazer`) — ② FileNameKeyword

| 항목 | 값 |
|:---|:---|
| **필수 키워드** | **`hold`** — 이게 없는 파일명은 전부 일반 단노트 |
| Head 키워드 | `시작` `start` |
| Tail 키워드 | `끝` `end` |
| `tailFirst` | 미확인 (안전하게 `true`) |
| `nestingPolicy` | `Fifo` |

> DEFLATE와 같은 전략이지만 **필수 키워드가 있다는 점이 다릅니다.** `synth_start.wav` 는 DEFLATE에서도 스타게이저에서도
> 홀드가 아닙니다 — 범용 접미사를 기본 키워드에 넣으면 안 되는 이유입니다.

### 스타트레일 (`startrail`) — ① KeyValue

| 항목 | 값 |
|:---|:---|
| Head 키 | `02` |
| Tail 키 | `03` |
| `nestingPolicy` | `Fifo` |

> 홀드는 **키음 값** `02`/`03` 이고, 게이트 개폐는 **채널** `04`/`05` 입니다. 둘은 다른 층입니다.
> 게이트 채널은 편집 대상(`16,11~15,18`) 밖이라 원문 보존으로만 통과하므로 짝 맞추기와 무관합니다.
> 게이트 **레인**(`16` Blue / `18` Red)에 찍는 노트는 편집 대상입니다.

### 건볼트 (`gunvolt`) — ① KeyValue (N:M)

| `HoldKind` | Head 키 | Tail 키 |
|:---|:---|:---|
| `Hold` | `02` | `19` |
| `Arc` | `11` `12` `13` `14` `15` `16` `17` `18` (8방향) | `1A` `1B` |

> [!IMPORTANT]
> **아크는 시작 8종 ↔ 끝 2종의 N:M 입니다.** 1:1 페어 레코드로는 표현할 수 없습니다.
> 어느 시작이 어느 끝과 짝지어지는지(`Fifo`/`Lifo`)는 **미확인**입니다 → [spec §12 Q3](hold_pairing_spec.md).
>
> 8방향 플릭(`03`~`0A`)은 짝이 없는 단발이므로 홀드 대상이 아닙니다.

### ~~뮤즈 대시 (`muse_dash`)~~ — [지원 제외]

> [!WARNING]
> **공식 작업 대상 제외:** 6자리 UID 체계의 난해함과 출현 순서 전파로 인한 극심한 작업 시간 소요(340노트에 4시간)로 인해 **공식 채보 작성 대상에서 제외**되었습니다. 아래 내용은 참고 및 기술 보존용입니다.

파일명 앞 6자리 UID의 숫자 자리로 "홀드 대상"을 판별하고, **같은 채널에서 홀수 번째 = 시작 / 짝수 번째 = 끝**입니다.

| 항목 | 값 |
|:---|:---|
| 타입 자리 → `Hold` | `02` |
| 타입 자리 → `Sandbag` | `04` |
| 프리픽스 규칙 (**우선**) | `0002`=하트 · `0003`=스코어 · `0004`=씬 전환 → 홀드 대상 아님 |
| 수열 분리 | `Hold` 와 `Sandbag` 를 **따로 센다** (미확인 → [Q1](hold_pairing_spec.md)) |

> [!CAUTION]
> **이 전략만 전파가 있습니다.** 수열 중간에 홀드를 끼워 넣으면 **그 뒤 전부가 뒤집힙니다.**
> 47마디를 고치고 60마디부터 무너지는 증상의 정체입니다. 검사기는 **첫 어긋난 자리**만 지목해야 합니다.
>
> 숫자 자리 번호가 모호합니다 — 가이드는 "2~3번째 자리"라고 적고 패턴은 `xx02xx`, 예시는 `010201`(3~4번째 자리)입니다.
> 프로파일에는 **0-based `offset`/`length`** 로만 적습니다 → [Q2](hold_pairing_spec.md).
>
> 파일명 끝 `_dt[초]` 는 오프셋 델타입니다. **접미사가 이미 다른 의미로 쓰이는 프로파일**이라는 증거입니다.

## 🚫 3. 모든 프로파일에 공통인 것

* **편집 대상 채널은 `16,11,12,13,14,15,18` 뿐입니다**([`BmsParser`](../../bms%20editer/Services/BmsParser.cs)). 프로파일의 "편집 레인"은 이 중 **어디를 쓰는지**를 좁히는 것이고, 넓히지는 못합니다.
* **표준 LN 채널 `51~59` 와 `#LNOBJ` 는 어느 프로파일도 쓰지 않습니다.** 원문 보존으로 통과만 합니다. 범위 밖입니다.
* **프로파일이 지정되지 않으면 홀드 감지가 전부 꺼집니다.** 일반 BMS는 지금과 똑같이 동작합니다.
* 차트가 자기 프로파일을 들고 다닙니다: `#BMSEDITER_PROFILE <id>` → [spec §10](hold_pairing_spec.md)

## ➕ 4. 게임을 추가하는 절차

1. 게임 모드의 파서 소스를 읽고 `guides/` 에 **가이드 문서** 하나를 씁니다.
2. **이 문서 §1 표에 한 줄** 추가합니다 (검증은 `⬜` 로 시작).
3. 전략이 ①②③ 중 무엇인지 정하고 **§2에 파라미터 절**을 씁니다. 셋 중 아무것도 아니면 [spec §2](hold_pairing_spec.md) 에 네 번째 전략을 추가해야 하므로, 먼저 그게 정말 맞는지 확인하십시오.
4. `Assets/profiles/<id>.json` 을 추가합니다. **코드는 고치지 않습니다.**
5. 실제로 채보를 만들어 보고 `⬜` → `✅` 로 바꿉니다. 그때까지는 화면에 미검증 배너가 뜹니다.
